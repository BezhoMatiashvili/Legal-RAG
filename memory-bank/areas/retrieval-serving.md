# Retrieval & serving (search pipeline, rerank, MCP server, serverless)
> Drill-down memory. Not auto-loaded — opened per the pre-modification ritual in INDEX.md. Anchors linted by ingest/scripts/gen_code_map.py --check.

## Overview
The serving side is one Python package (`ingest/ingest/`) exposed through the `legal_rag` MCP stdio server registered in `.mcp.json`. All 8 tools live in `ingest/ingest/mcp_server.py` and delegate to a shared pipeline: BGE-M3 dense+sparse query embedding (`ingest/ingest/embedding.py`), Qdrant server-side RRF fusion with EN/KA language routing (`ingest/ingest/search.py:hybrid_search`), and a bge-reranker-v2-m3 cross-encoder second stage (`ingest/ingest/rerank.py`) that runs locally on CPU (length-bucketed, thread-pinned) or on a remote GPU pod via `ingest/ingest/rerank.py:RemoteBGEReranker`, with automatic RRF-fallback in `legal_search` when the remote reranker fails. With `SEARCH_BACKEND=remote`, the same tool coroutines execute on a RunPod serverless worker (`ingest/serverless/handler.py`) bundling a local Qdrant binary plus both models; the local MCP server becomes a stdlib-only thin client (`ingest/ingest/remote_search.py:RunPodQueueClient`). Corpus data reaches the worker via a manifest-last snapshot publish protocol (`ingest/scripts/publish_snapshot.py` → `ingest/serverless/qdrant_boot.py`). Env config is loaded once at process spawn via python-dotenv in `ingest/ingest/config.py`, which is why the MCP server must be reconnected via /mcp after any code or .env edit. Query analytics are local-only JSONL (`ingest/ingest/querylog.py`); a read-only dashboard runs on :8770 (`ingest/scripts/session_monitor.py`).

## Entrypoints
- `uv run --directory ingest python -m ingest.mcp_server` → `ingest/ingest/mcp_server.py:main` — the `legal_rag` MCP stdio server; registered in `.mcp.json` with OMP_NUM_THREADS=14 / MKL_NUM_THREADS=14.
- `python -m ingest search <query> [--no-rerank]` → `ingest/ingest/__main__.py:_cmd_search` — CLI hybrid search (same pipeline, no MCP).
- RunPod serverless container CMD → `ingest/serverless/handler.py:main` — boots Qdrant, eager-loads models, serves the op queue.
- `python ingest/scripts/publish_snapshot.py --create|--upload|--verify|--cleanup` — snapshot publish workflow from the local write-master to the serverless volume (`ingest/scripts/publish_snapshot.py:create` / `ingest/scripts/publish_snapshot.py:upload` / `ingest/scripts/publish_snapshot.py:verify` / `ingest/scripts/publish_snapshot.py:cleanup`).
- `python ingest/scripts/runpod_rerank.py up|down` — GPU rerank pod orchestrator (`ingest/scripts/runpod_rerank.py:up`; `down` is a `__main__` branch that terminates from the saved pod.id); serves `ingest/scripts/runpod_rerank_server.py:score` over an SSH tunnel at localhost:8900 (RERANK_REMOTE_URL).
- `python ingest/scripts/session_monitor.py` → `ingest/scripts/session_monitor.py:main` — read-only dashboard on :8770 (RAM/swap, MCP server count, GPU pod health at localhost:8900/health, query-log latencies, embed coverage).
- `ingest/docker-compose.yml` — local write-master Qdrant v1.18.2 (container `legal-qdrant`, loopback :6333/:6334).

## Modules

### ingest/ingest/mcp_server.py
The `legal_rag` MCP stdio server: all 8 tool implementations, lazy model singletons, the search semaphore, remote-backend dispatch, query logging, pidfile singleton guard.
- `ingest/ingest/mcp_server.py:legal_search` — primary RAG tool; `ingest/ingest/mcp_server.py:SearchInput` validates query/top_k/filters. On reranker exception, if `ingest/ingest/mcp_server.py:_is_remote_reranker` is true it retries `hybrid_search` with `reranker=None` (RRF-fallback); a local reranker exception re-raises. calls: `ingest/ingest/search.py:hybrid_search`, `ingest/ingest/search.py:detect_language`, `ingest/ingest/mcp_server.py:_remote_op` (remote mode), `ingest/ingest/mcp_server.py:_log_query`. called_by: MCP clients, `ingest/serverless/handler.py:OPS`.
- `ingest/ingest/mcp_server.py:legal_get_document` — reassembles a full doc: scrolls all chunks for source+document_id, sorts by chunk_index, de-duplicates chunk overlap via `ingest/ingest/mcp_server.py:_stitch_overlap`. calls: `ingest/ingest/mcp_server.py:_scroll_all`, `_stitch_overlap`. called_by: MCP clients, serverless OPS.
- `ingest/ingest/mcp_server.py:legal_lookup` — exact identifier retrieval (document_number / registration_code / document_id), no model load. calls: `ingest/ingest/search.py:build_filter`, `ingest/ingest/mcp_server.py:_scroll_all`, `ingest/ingest/mcp_server.py:_dedup_documents`. called_by: MCP clients, serverless OPS.
- `ingest/ingest/mcp_server.py:legal_browse` — non-semantic listing by structured filters, deduped per doc, date-sorted, offset/limit paginated in memory. calls: `ingest/ingest/search.py:build_filter`, `_scroll_all`, `_dedup_documents`. called_by: MCP clients, serverless OPS.
- `ingest/ingest/mcp_server.py:legal_get_document_versions` — matsne amendment lineage via shared registration_code; marks status=='in_force' as current. calls: `build_filter`, `_scroll_all`, `_dedup_documents`. called_by: MCP clients, serverless OPS.
- `ingest/ingest/mcp_server.py:legal_collection_info` / `ingest/ingest/mcp_server.py:legal_health` / `ingest/ingest/mcp_server.py:ingest_status` — introspection: collection stats + per-source facets; health probe (remote mode uses `ingest/ingest/remote_search.py:RunPodQueueClient.health` — never wakes/bills a worker — and reports `ingest/ingest/mcp_server.py:_publish_manifest`); watcher freshness via `ingest/ingest/pipeline.py:_load_watch_state`. ingest_status is local-only (absent from serverless OPS).
- `ingest/ingest/mcp_server.py:_search_semaphore` — asyncio.Semaphore(1) serializing the embed+rerank hot path; two concurrent searches co-thrash swap on the 30GB box (observed ~597s each vs ~190s isolated). called_by: `legal_search`.
- `ingest/ingest/mcp_server.py:_get_embedder` / `ingest/ingest/mcp_server.py:_get_reranker` — double-checked lazy singletons via asyncio.to_thread; `_get_reranker` picks `RemoteBGEReranker` when cfg.rerank_remote_url is set, else `BGEReranker`; returns None when rerank disabled. calls: `ingest/ingest/embedding.py:BGEM3Embedder`, `ingest/ingest/rerank.py:BGEReranker`, `ingest/ingest/rerank.py:RemoteBGEReranker`. called_by: `legal_search`, `ingest/serverless/handler.py:_warmup`.
- `ingest/ingest/mcp_server.py:_use_remote` / `ingest/ingest/mcp_server.py:_remote_op` / `ingest/ingest/mcp_server.py:_get_remote_client` — SEARCH_BACKEND=remote thin-client dispatch; each tool becomes one `RunPodQueueClient.call(op, params)` returning the worker's pre-formatted string; deliberately NO silent local fallback. called_by: every legal_* tool.
- `ingest/ingest/mcp_server.py:_enforce_singleton` — pidfile guard (ingest/.state/mcp_server.pid): SIGTERMs a prior live server (cmdline-verified via `ingest/ingest/mcp_server.py:_is_our_server`) so /mcp reconnects don't stack ~4.6GB processes; best-effort, never fatal. called_by: `main`.
- `ingest/ingest/mcp_server.py:_log_query` / `ingest/ingest/mcp_server.py:_log_query_remote` — best-effort local query logging; remote records carry mode='remote' and empty hits (n_hits=0 must NOT be read as "no results"). calls: `ingest/ingest/querylog.py:build_query_record`, `ingest/ingest/querylog.py:append_query_log`. called_by: `legal_search`.

### ingest/ingest/search.py
The retrieval pipeline: payload filter builder, EN/KA routing, two-stage hybrid search with Qdrant server-side RRF fusion, rerank gating, optional diversity.
- `ingest/ingest/search.py:hybrid_search` — stage 1: Prefetch dense (QuantizationSearchParams rescore=True explicit) + sparse branches, FusionQuery(RRF) in Qdrant, candidate pool = rerank_candidates (80) when a reranker is passed else top_k; stage 2: `rerank_points`. Routing (`route=True`): drops the sparse branch for English queries (BGE-M3 learned-sparse is lexical; EN tokens are noise against Georgian). calls: `ingest/ingest/embedding.py:BGEM3Embedder.encode_query`, `ingest/ingest/search.py:build_filter`, `detect_language`, `rerank_points`, `diversify`. called_by: `ingest/ingest/mcp_server.py:legal_search`, `ingest/ingest/__main__.py:_cmd_search`, eval harness.
- `ingest/ingest/search.py:detect_language` — 'ka' iff the query contains Georgian script, else 'en'; drives sparse routing and the query-log route field. called_by: `hybrid_search`, mcp_server logging, `ingest/eval/backend.py`, `ingest/eval/translations.py`.
- `ingest/ingest/search.py:build_filter` — AND filter over indexed payload fields: MatchValue (source/language/document_type/court/document_id/document_number/registration_code/status/is_consolidated), MatchText (parties, contains→text), DatetimeRange over 'date'. called_by: `hybrid_search`, `legal_lookup`, `legal_browse`, `legal_get_document_versions`.
- `ingest/ingest/search.py:rerank_points` — scores the fused pool with reranker.score, OVERWRITES each point's .score with the calibrated 0..1 relevance, sorts, drops below min_score (default gate 0.3), returns top_k. called_by: `hybrid_search`, `ingest/eval/backend.py`.
- `ingest/ingest/search.py:diversify` — optional per-doc cap and/or MMR (MMR needs candidate vectors; degrades to cap-only without them). called_by: `hybrid_search`, `ingest/eval/backend.py`.

### ingest/ingest/rerank.py
Second-stage cross-encoder (bge-reranker-v2-m3) — the biggest precision lever — CPU implementation plus a remote GPU drop-in.
- `ingest/ingest/rerank.py:BGEReranker` — transformers AutoTokenizer(fast) + AutoModelForSequenceClassification; `ingest/ingest/rerank.py:BGEReranker.score` length-buckets candidates (sort by length, batch, scatter back — identical scores, fewer padded FLOPs), sigmoid of the logit, max_length 512. calls: `ingest/ingest/rerank.py:_configure_cpu_threads`. called_by: `ingest/ingest/mcp_server.py:_get_reranker`, eval harness.
- `ingest/ingest/rerank.py:_configure_cpu_threads` — thread-pin: torch.set_num_threads(OMP_NUM_THREADS or cpu_count) + interop=1 so torch and OpenMP agree (OMP_NUM_THREADS=14 comes from `.mcp.json`). called_by: `BGEReranker.__init__` (cpu only).
- `ingest/ingest/rerank.py:RemoteBGEReranker` — drop-in with `device = "remote"` (the marker `ingest/ingest/mcp_server.py:_is_remote_reranker` keys on for RRF-fallback); POSTs {query, texts} to RERANK_REMOTE_URL /score (GPU pod via SSH tunnel); stdlib urllib only. called_by: `ingest/ingest/mcp_server.py:_get_reranker`, `ingest/eval/evaluate.py:qdrant_deps`.

### ingest/ingest/qdrant_store.py
Qdrant client construction, collection schema, deterministic point IDs, payload construction shared by ingest and search.
- `ingest/ingest/qdrant_store.py:make_client` — QdrantClient factory (timeout=120); refuses a non-local QDRANT_URL without QDRANT_API_KEY and refuses to send the key over non-HTTPS. called_by: mcp_server `_get_client`, pipeline, eval, scripts.
- `ingest/ingest/qdrant_store.py:ensure_collection` — creates named vectors {'dense' 1024-d cosine on_disk, 'sparse'}, on_disk_payload, INT8 scalar quantization always_ram (hybrid_search's rescore=True depends on this); payload indexes from `ingest/ingest/qdrant_store.py:KEYWORD_FIELDS` + `ingest/ingest/sources.py:PROMOTED_KEYWORD_FIELDS`, `ingest/ingest/qdrant_store.py:TEXT_FIELDS` + `ingest/ingest/sources.py:PROMOTED_TEXT_FIELDS` (MULTILINGUAL tokenizer for Georgian word boundaries), `ingest/ingest/qdrant_store.py:DATETIME_FIELDS`, bool is_consolidated, integer chunk_index/consolidated_count. called_by: pipeline (ingest side).
- `ingest/ingest/qdrant_store.py:build_payload` — writes every payload field serving relies on (source, document_id, chunk_index, title, date/date_raw, language, document_type, court, source_url, document_number, registration_code, parties, status, is_consolidated, consolidated_count, in_force_date, expiry_date, heading, token_count, char_start/char_end, text, content_hash); promoted fields via setdefault so they never shadow canonical keys. called_by: `ingest/ingest/pipeline.py` embed paths.
- `ingest/ingest/qdrant_store.py:point_id` — uuid5(namespace, 'source:document_id:chunk_index') — deterministic, idempotent upserts. called_by: pipeline.

### ingest/ingest/config.py
Env-driven frozen Config dataclass; python-dotenv load_dotenv() runs at import time — the root of the .env-cached-at-spawn behavior.
- `ingest/ingest/config.py:load_config` — reads QDRANT_URL / COLLECTION_NAME (default georgian_legal), SEARCH_BACKEND (local|remote), RUNPOD_ENDPOINT_ID/API_KEY/timeout, EMBED_MODEL (BAAI/bge-m3), RERANK_ENABLED / RERANK_MODEL (BAAI/bge-reranker-v2-m3) / RERANK_CANDIDATES (80) / RERANK_MIN_SCORE (0.3) / RERANK_REMOTE_URL, chunking knobs, QUERY_LOG_*; query log defaults to ingest/.state/queries.jsonl. called_by: mcp_server `_get_cfg`, `__main__`, eval, scripts, serverless handler (via mcp_server).
- `ingest/ingest/config.py:retrieval_fingerprint` — 16-hex sha256 of the result-determining knobs (collection, models, rerank config, chunking); stamped into every MCP response footer and query-log record; recommended config = 81c807b279399098. called_by: mcp_server, eval explog.
- `ingest/ingest/config.py:_device_opt` — defends against python-dotenv leaking inline .env comments as device values. called_by: `load_config`.

### ingest/ingest/embedding.py
BGE-M3 query/passage embedding: one model yields the 1024-d dense vector and the learned-sparse lexical weights for the hybrid's two branches.
- `ingest/ingest/embedding.py:BGEM3Embedder` — wraps FlagEmbedding BGEM3FlagModel (lazy heavy import); `ingest/ingest/embedding.py:BGEM3Embedder.encode_query` → Embedded(dense, Sparse(indices, values)). called_by: `ingest/ingest/mcp_server.py:_get_embedder`, `hybrid_search` (via embedder arg), pipeline/embed jobs.

### ingest/ingest/remote_search.py
Stdlib-only RunPod Serverless queue-API client used by SEARCH_BACKEND=remote.
- `ingest/ingest/remote_search.py:RunPodQueueClient` — `ingest/ingest/remote_search.py:RunPodQueueClient.call` POSTs /run then polls /status within a client-side budget, tolerating poll blips; on budget expiry deliberately does NOT cancel (raises `EndpointWarmingUp` so the cold-starting worker keeps warming and the retry lands warm); `RunPodQueueClient.health` = GET /health (never wakes a worker); sends a browser UA (Cloudflare 403s default urllib). called_by: `ingest/ingest/mcp_server.py:_get_remote_client` / `_remote_op`, `ingest/scripts/publish_snapshot.py:verify`, `ingest/scripts/session_monitor.py`.
- `ingest/ingest/remote_search.py:EndpointWarmingUp` / `ingest/ingest/remote_search.py:RemoteOpError` — agent-facing actionable errors (cold start vs worker/platform failure), rendered into tool output by `_remote_op`.

### ingest/ingest/querylog.py
Local append-only JSONL query analytics. PII guardrail: no network I/O ever; per hit only document_id/source/chunk_index/score (never text).
- `ingest/ingest/querylog.py:build_query_record` — one record: timestamp, query, non-empty filters, top_k, mode, route (ka/en), fingerprint, latency_ms, n_hits, id-only hits. called_by: `_log_query` / `_log_query_remote`.
- `ingest/ingest/querylog.py:append_query_log` — appends one JSON line to the configured queries.jsonl (per-line atomic). called_by: mcp_server; read by `ingest/scripts/session_monitor.py` latency panels.

### ingest/serverless/handler.py
RunPod serverless worker: the entire read path (Qdrant + BGE-M3 + reranker + op dispatcher) in one scale-to-zero container; reuses the MCP tool coroutines unchanged so remote responses are byte-identical.
- `ingest/serverless/handler.py:handler` — queue-job dispatcher: {'op','params'} → {'result': str} or {'error': ...}; per-job self-heal via `ingest/serverless/qdrant_boot.py:restore_pending` (catches publishes that landed after a warm/FlashBoot revival); 'refresh' op retries a failed boot / forces a restore re-check; prepends a STALE-data warning when the last restore errored. calls: tool coroutines via `OPS`, `ingest/serverless/qdrant_boot.py:maybe_restore`. called_by: runpod.serverless runtime.
- `ingest/serverless/handler.py:OPS` — op → (tool coroutine, pydantic input model): search/get_document/lookup/browse/versions/collection_info/health; ingest_status intentionally absent (watcher state is local-only). called_by: `handler`.
- `ingest/serverless/handler.py:_boot` — FAIL-SOFT cold-start: `ensure_running` + `maybe_restore`; stores errors instead of exiting (no billed crash-loop). The module hard-assigns SEARCH_BACKEND=local (never route the worker to itself) and QUERY_LOG_ENABLED=false (no logs off-box) BEFORE importing ingest. called_by: module import, `handler` ('refresh').
- `ingest/serverless/handler.py:_warmup` — eager model load (EAGER_LOAD=1 default) so FlashBoot snapshots a worker with both models resident. calls: `ingest/ingest/mcp_server.py:_get_embedder`, `_get_reranker`. called_by: `ingest/serverless/handler.py:main`.

### ingest/serverless/qdrant_boot.py
Boots the worker-local Qdrant (static binary, storage on the network volume) and implements the worker side of the manifest-last snapshot publish/restore protocol.
- `ingest/serverless/qdrant_boot.py:ensure_running` — spawns /opt/qdrant/qdrant with storage + snapshots-path on /runpod-volume, loopback only; retries up to 300s because a draining old worker may still hold the exclusive storage lock during a rollout (endpoint must run max workers = 1). called_by: `handler` boot path.
- `ingest/serverless/qdrant_boot.py:maybe_restore` — compares publish/manifest.json vs publish/ACTIVE; if different: sha256-verify the ~24GB snapshot (refuses on mismatch = incomplete upload), hardlink/copy into the snapshots dir (Qdrant 403s file:// recover from outside it), PUT snapshots/recover?wait=true, verify restored points_count against the manifest, write ACTIVE last; when up-to-date it still verifies the collection exists (stale ACTIVE on a wiped volume → re-restore). calls: `ingest/serverless/qdrant_boot.py:needs_restore`. called_by: `handler` (boot, per-job self-heal, refresh).
- `ingest/serverless/qdrant_boot.py:needs_restore` / `ingest/serverless/qdrant_boot.py:restore_pending` — cheap manifest-vs-ACTIVE comparison (identity keys: snapshot/sha256/collection only); `restore_pending` is the per-job two-file check for warm workers.

### ingest/scripts/publish_snapshot.py
Local side of the publish protocol: snapshot the write-master Qdrant, resumable multipart upload to the RunPod volume's S3 gateway, manifest uploaded LAST as the atomic completion signal, then remote verification.
- `ingest/scripts/publish_snapshot.py:create` — POST snapshots?wait=true on legal-qdrant, docker-cp the snapshot to ingest/.state/publish/, sha256 it, write manifest.json {snapshot, sha256, size_bytes, points_count, collection, qdrant_version}; reaps stale container-side snapshots.
- `ingest/scripts/publish_snapshot.py:upload` — resumable multipart upload (95MB parts — larger 413s at the gateway edge proxy) keyed by upload_state.json + server ListParts; aborts superseded uploads (orphaned parts bill storage); `ingest/scripts/publish_snapshot.py:_publish_manifest_object` uploads publish/manifest.json LAST.
- `ingest/scripts/publish_snapshot.py:verify` — sends the 'refresh' op (not health — warm workers never re-run the boot restore) with PUBLISH_VERIFY_TIMEOUT (default 1800s, deliberately not the 240s day-to-day budget), then checks restore status and point parity against the manifest; exit code is the verdict. calls: `ingest/ingest/remote_search.py:RunPodQueueClient`.

### ingest/scripts/runpod_rerank.py + runpod_rerank_server.py
On-demand GPU reranking: provision a pod, run the stdlib HTTP rerank server on it, tunnel :8900 over SSH, and ALWAYS terminate the pod on exit (atexit + signal handlers via `ingest/scripts/runpod_rerank.py:_terminate`).
- `ingest/scripts/runpod_rerank.py:up` — provision (reuses `ingest/scripts/runpod_orchestrate.py` gql/ssh helpers), start the server, open the -L 8900 tunnel; `down` (a `__main__` branch) emergency-terminates from the saved pod.id — a pod was once orphaned and billed, always run down.
- `ingest/scripts/runpod_rerank_server.py:score` — mirrors `ingest/ingest/rerank.py:BGEReranker.score` EXACTLY (same model, fast tokenizer, max_length=512, sigmoid) on CUDA — score parity with CPU is the contract `RemoteBGEReranker` relies on.

### ingest/scripts/session_monitor.py
Loopback-only stdlib dashboard on :8770 — Claude session activity, RAM/swap, Qdrant RAM, running MCP server count, GPU pod health (localhost:8900/health), serverless endpoint health, recent legal_search latencies from the query log, embed coverage.
- `ingest/scripts/session_monitor.py:build_state` — aggregates all panels; `ingest/scripts/session_monitor.py:rag_state` reads ingest/.state/queries.jsonl. Never writes. called_by: HTTP handler; run by systemd legal-monitor.service or operator.

Local write-master runs in docker (`legal-qdrant`, v1.18.2); serverless worker runs its own copy from a restored snapshot.

- `ingest/.state/reports/ingest-*.json` + watch state — read by `ingest/ingest/mcp_server.py:ingest_status` via `ingest/ingest/pipeline.py:_load_watch_state` for freshness reporting (written by the ingestion area).
- Every MCP response footer and query-log record carries `ingest/ingest/config.py:retrieval_fingerprint` (recommended config 81c807b279399098).

## Hazards
- Env/config caching at spawn: `ingest/ingest/config.py` calls load_dotenv() at import time and mcp_server caches Config/client/embedder/reranker in module-global singletons — editing ingest/ code or ingest/.env does NOTHING to a running legal_rag server; it silently serves stale code until reconnected via /mcp.
- The RRF-fallback in `legal_search` keys on `reranker.device == "remote"` (`ingest/ingest/mcp_server.py:_is_remote_reranker` ↔ `RemoteBGEReranker` setting `device = "remote"`); renaming that attribute silently turns dead-GPU-pod degradation into a hard tool error. A LOCAL reranker exception is deliberately re-raised (no fallback).
- Score parity contract: `ingest/scripts/runpod_rerank_server.py:score` must mirror `ingest/ingest/rerank.py:BGEReranker.score` exactly (model, fast tokenizer, max_length=512, sigmoid) — drift silently changes rerank scores and the 0.3 min-score gate semantics, invalidating eval baselines.
- `ingest/ingest/search.py:hybrid_search` explicitly pins QuantizationSearchParams(rescore=True); dropping it would silently rank on int8 vectors and quietly cost recall/nDCG.
- `build_filter`'s MatchText fields (parties, contains→text) need the TEXT payload indexes with the MULTILINGUAL tokenizer created by `ingest/ingest/qdrant_store.py:ensure_collection`; a collection created any other way makes those filters fail or return nothing.
- `retrieval_fingerprint` only hashes the listed knobs — adding a behavior-changing knob (routing, diversity, sparse weighting) without adding it to the material dict makes different behaviors share a fingerprint, corrupting experiment traceability.
- Serverless endpoint MUST run max workers = 1: Qdrant holds an exclusive storage-dir lock on the shared volume; `ensure_running` only tolerates the brief rollout overlap by retrying.
- Publish ordering is load-bearing: manifest.json uploaded LAST (`ingest/scripts/publish_snapshot.py:_publish_manifest_object`) and ACTIVE written only after a verified restore (`ingest/serverless/qdrant_boot.py:maybe_restore`) — reordering either side lets a half-uploaded ~24GB snapshot get restored or a failed restore be marked applied. `needs_restore` compares only snapshot/sha256/collection; renaming those keys breaks change detection.
- Qdrant version pinned to v1.18.2 in BOTH `ingest/docker-compose.yml` and `ingest/serverless/Dockerfile` (snapshots are only compatible within a minor version); a drive-by upgrade on one side breaks write-master ↔ worker snapshot compatibility.
- `ingest/serverless/handler.py` hard-assigns SEARCH_BACKEND=local and QUERY_LOG_ENABLED=false BEFORE importing ingest — moving that import above the env assignment reintroduces the self-RPC loop and the off-box query-log privacy leak.
- Query-log semantics: remote-mode records have mode='remote' and empty hits by design (hit ids stay on the worker) — analytics reading n_hits=0 as "no results" is wrong.
- RAM co-thrash: `_search_semaphore` and `_enforce_singleton` exist because BGE-M3 + reranker ≈ 4.6GB per process on a 30GB box; removing either reintroduces the observed 190s→600s swap-thrash and stacked leaked servers. OMP_NUM_THREADS=14 comes from `.mcp.json` — launching the server another way loses the thread pin.
- `legal_browse` scrolls the ENTIRE filter match into memory before paginating — a broad filter (e.g. source only, ~100k+ chunks) is slow and memory-heavy; limit/offset do not push down to Qdrant.
- RunPod client budget semantics: `RunPodQueueClient.call` deliberately never cancels a timed-out job (lets the cold start finish so the retry lands warm), and publish verify uses PUBLISH_VERIFY_TIMEOUT=1800s, NOT the 240s day-to-day budget — "fixing" either the wrong way breaks cold-start recovery. Some RunPod hosts Cloudflare-403 non-browser UAs; the UA header is required.
- GPU rerank pods bill until terminated: `runpod_rerank.py down` / its atexit `_terminate` path is the only guard; a pod has already been orphaned once.
- `ingest/ingest/qdrant_store.py:make_client` refuses a non-local QDRANT_URL without an API key and refuses non-HTTPS key transport — a well-meant "simplification" there removes the secret-leak guard.

## Cross-area
- Ingest writes → search reads: `ingest/ingest/qdrant_store.py:build_payload` (called from `ingest/ingest/pipeline.py` embed paths, see ingest-core.md) produces every payload field serving depends on — `ingest/ingest/mcp_server.py:_hit_dict` / `_dedup_documents` / `_stitch_overlap` read them and `ingest/ingest/search.py:build_filter` filters on the same names.
- Index schema contract: `ingest/ingest/qdrant_store.py:ensure_collection` (invoked from the ingestion area) creates the payload indexes and named vectors that `hybrid_search`'s Prefetch(using='dense'/'sparse') and rescore=True assume; promoted fields come from `ingest/ingest/sources.py:PROMOTED_KEYWORD_FIELDS` / `ingest/ingest/sources.py:PROMOTED_TEXT_FIELDS`.
- Eval area consumes the pipeline (see eval-ops.md): `ingest/eval/backend.py:QdrantBackend` imports `ingest/ingest/search.py:detect_language`, `rerank_points`, `diversify` and re-implements mode variants around them; `ingest/eval/evaluate.py:qdrant_deps` constructs `ingest/ingest/rerank.py:RemoteBGEReranker` from RERANK_REMOTE_URL for GPU-offloaded sweeps; `ingest/ingest/config.py:retrieval_fingerprint` is the experiment identity in ingest/eval/experiments.jsonl.
- MCP tools are shared code, not RPC-only: `ingest/serverless/handler.py:OPS` imports the tool coroutines from `ingest/ingest/mcp_server.py` directly (FastMCP.tool() returns the original function), so any change to a tool's output format changes local and remote serving simultaneously.
- `ingest_status` reaches into the ingestion area: `ingest/ingest/pipeline.py:_load_watch_state` and .state/reports/ingest-*.json (written by the daily watcher, see ingest-core.md) feed freshness reporting.
- Snapshot publish couples areas: `ingest/scripts/publish_snapshot.py:create` snapshots the LOCAL write-master collection (fed by the ingest pipeline) and `ingest/serverless/qdrant_boot.py:maybe_restore` restores it on the worker.
- Coverage verification (ingestion area): ingest/scripts/verify_all_embedded.py checks id-parity using the same SourceSpec.id_fields identity that `ingest/ingest/qdrant_store.py:point_id` encodes; `ingest/scripts/session_monitor.py` (:8770) renders its embed_coverage.json.
- `.mcp.json` (repo root) is the consumer-side registration of `ingest/ingest/mcp_server.py:main` and injects OMP_NUM_THREADS=14 / MKL_NUM_THREADS=14 that `ingest/ingest/rerank.py:_configure_cpu_threads` reads for the CPU thread-pin.
